title: "Understanding the Output"
description: "What every column, number, and score means in Skylos scan results"
---

When you run Skylos, it prints a summary, a scan assessment, and then tables
grouped by category. This guide explains what each part means. The examples
come from Skylos 5.1.1.

## Summary

```text
╭──────────────────────────────────────────────╮
│ Static Analysis Results                      │
│ 0 defects · 10 review · 0 advice in 0 groups │
│ Analyzed 3 file(s)                           │
╰──────────────────────────────────────────────╯
```

Every finding is one of three types:

| Type | Meaning |
|--------|---------|
| **Defect** | Proven problem; fix it |
| **Review** | Likely problem; a person should check the evidence |
| **Advice** | Optional improvement; hidden by default (`--all-advice` lists it) |

## Scan Assessment

```text
                Scan assessment
┏━━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃ Area            ┃ Result                                                           ┃
┡━━━━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┩
│ Risk            │ CRITICAL · 6 unresolved findings                                 │
│ Maintainability │ 0 advice findings · 5 rules checked · 0 affected files           │
│ Dead code       │ 4 candidates to review before removal · confidence 60–100%       │
│ Gate            │ Not evaluated · use --gate to check configured limits            │
└─────────────────┴──────────────────────────────────────────────────────────────────┘
Coverage: partial; not assessed: ai_defects, dependencies; some issues may not be reported
```

| Row | Meaning |
|--------|---------|
| **Risk** | The worst severity among Defect and Review findings |
| **Maintainability** | Quality advice and the rules measured |
| **Dead code** | How many candidates, and their confidence range |
| **Gate** | `PASSED`, `FAILED`, or "Not evaluated" without `--gate` |
| **Coverage** | Which analyzers did not run. Add `-a` to run them all |

## Finding Tables

Every category uses the same columns:

```text
───────────────────────── Security ─────────────────────────
┏━━━━━━━━┳━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━┓
┃ Type   ┃ Severity ┃ Rule              ┃ Message                              ┃ Location         ┃
┡━━━━━━━━╇━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━┩
│ Review │ CRITICAL │ SQL injection     │ Possible SQL injection: tainted or   │ api/users.py:12  │
│        │          │ SKY-D211          │ string-built query.                  │                  │
│        │          │                   │ Static source: request data          │                  │
│        │          │                   │ `request.args.get`                   │                  │
│        │          │                   │ Static sink: SQL text passed to      │                  │
│        │          │                   │ .execute()                           │                  │
│        │          │                   │ Symbol: get_user                     │                  │
│ Review │ CRITICAL │ Command injection │ Possible command injection           │ utils/shell.py:8 │
│        │          │ SKY-D212          │ (subprocess shell=True): tainted     │                  │
│        │          │                   │ input.                               │                  │
└────────┴──────────┴───────────────────┴──────────────────────────────────────┴──────────────────┘
```

| Column | Meaning |
|--------|---------|
| **Type** | Defect, Review, or Advice |
| **Severity** | Risk level: **CRITICAL** > **HIGH** > **MEDIUM** > **LOW** |
| **Rule** | The rule name and its ID. Look the ID up in the [Rules Reference](/rules-reference) |
| **Message** | What was found, plus evidence lines such as the source, sink and symbol |
| **Location** | `file:line` where the issue occurs |

For a security finding, `skylos explain` replays the recorded source-to-sink
steps from a saved JSON report.

For one line per finding with no tables, use `--format concise`:

```text
api/users.py:12  SKY-D211  Possible SQL injection: tainted or string-built query.
```

## Dead Code (default)

```text
───────────────────────── Unused Functions ─────────────────────────
│ Review │ LOW │ Unused function │ Unused function: parse_config          │ api/users.py:15 │
│        │     │ SKY-U001        │ Confidence: 90% (public name)          │                 │
│        │     │                 │ Evidence: likely dead — no static      │                 │
│        │     │                 │ references were found [analyzer] · ... │                 │
```

The **Confidence** line shows how strong the evidence is that the code is
unused, from 0 to 100%:

- The default threshold is 60. Lower scores are not listed.
- Higher means fewer signs that anything calls it.
- Even at 100%, review before you delete. Dynamic calls (`getattr`, plugins,
  string-based dispatch) can hide a real use.

Change the threshold with `-c` / `--confidence`, for example `skylos . -c 80`.

## Reliability

Reliability findings describe release incompatibilities backed by evidence
across deployment, source, build, container, and target-contract files:

```text
Dockerfile:1  SKY-GPU001  reliability issue
deploy/rendered.yaml:42  SKY-DEP003  reliability issue
```

They are emitted under a separate top-level JSON bucket:

```json
{
  "reliability": [
    {
      "rule_id": "SKY-GPU001",
      "category": "RELIABILITY",
      "severity": "HIGH",
      "file": "Dockerfile",
      "line": 1,
      "message": "CUDA 12.4 requires NVIDIA driver branch 525 or newer.",
      "related_locations": [
        {
          "file": ".skylos/gpu-targets.yml",
          "line": 5
        }
      ]
    }
  ],
  "analysis_summary": {
    "reliability_count": 1
  }
}
```

`related_locations` records the other files and lines used to prove a
cross-file result. Diff-aware scans consider those supporting locations as
well as the primary location.

Reliability is activated by `--danger` / `-a`, or automatically when an exact
Reliability rule is requested with `--select`. `--category reliability` is a
display filter; it does not enable the analyzer by itself.

Reliability does not inflate `danger_count` or the Security grade. Gates use
the independent `max_reliability` threshold, which defaults to `0`. See
[Release Reliability](../release-reliability) for the Kubernetes and GPU
contracts.

## AI Defects (`--ai-defects`)

In JSON output, AI-defect checks are grouped under `ai_defects`:

```json
{
  "ai_defects": [
    {
      "rule_id": "SKY-D224",
      "category": "ai_defect",
      "defect_type": "api_signature_hallucination",
      "message": "Installed API does not accept keyword argument 'imaginary_timeout'."
    }
  ],
  "analysis_summary": {
    "ai_defects_count": 1
  }
}
```

This bucket currently includes `SKY-A101`, `SKY-A102`, `SKY-A103`,
`SKY-A104`, `SKY-A105`, `SKY-L012`, `SKY-L023`, `SKY-D222`, `SKY-D224`, and
`SKY-D225`.
Grouping is category-based, not only prefix-based: historical `SKY-L` and
`SKY-D` IDs are kept for compatibility when their catalog category is
`ai_defect`.

`SKY-D223` remains a security/supply-chain finding because an undeclared but
real dependency is not a hallucination.

See [AI Defect Verification](../ai-defects) for the method, output contract,
and blocking posture.

## Secrets (`--secrets`)

```text
───────────────────────── Secrets ─────────────────────────
│ Review │ CRITICAL │ Secret detected │ Potential stripe secret detected │ payments.py:1 │
│        │          │ SKY-S101        │ Provider: stripe                 │               │
│        │          │                 │ Preview: sk_l…1234               │               │
```

| Detail | Meaning |
|--------|---------|
| **Provider** | The service the secret belongs to (e.g. AWS, Stripe, GitHub) or "generic" for high-entropy strings |
| **Preview** | A masked snippet. Skylos never prints the full value |

## Quality (`--quality`)

```text
───────────────────────── Quality ─────────────────────────
│ Review │ MEDIUM │ Missing resource │ Resource 'sqlite3.connect' opened without │ api/users.py:10 │
│        │        │ cleanup          │ 'with' statement. Use a context manager   │                 │
│        │        │ SKY-L008         │ to ensure cleanup.                        │                 │
```

Threshold rules put the measured value and the limit in the message:

| Example message | What it means |
|---------|--------------|
| `Function has 6 required positional arguments (limit: 5)` | Too many arguments (`SKY-C303`). Group them or split the function |
| `Cyclomatic complexity is 18 (threshold: 10)` | Too many branches and loops (`SKY-Q301`). Extract helpers |
| `Nesting depth of 6 exceeds threshold of 3` | Code is nested too deep (`SKY-Q302`). Use early returns or guard clauses |
| Function longer than the limit (`SKY-C304`) | Break it into smaller functions |
| A string literal repeated more than the limit (`SKY-L027`) | Extract it to a named constant |

Below the summary, Skylos prints a **Maintainability measurements** table. It
shows, per rule, how many functions were measured and how many broke the limit.

## Dependency Vulnerabilities (`--sca`)

Advisories are grouped into one row per package:

| Column | Meaning |
|--------|---------|
| **Severity** | The worst advisory severity for that package |
| **Package** | The dependency name |
| **Installed** | The version recorded in your lockfile or exact pin |
| **Upgrade to** | The lowest version that fixes the advisories, when known |
| **Advisories** | The CVE or advisory IDs |
| **Location** | The lockfile or manifest line |

For PyPI packages, the JSON output also records a reachability verdict in
`metadata.reachability_verdict`: `reachable`, `unreachable_static`,
`unreachable_dynamic`, or `inconclusive`.

Every `--sca` run also prints a coverage receipt: what was queried, what could
not be resolved, and which manifests are not supported. See
[Dependencies and Supply Chain](/supply-chain).

## Circular Dependencies

Circular imports (`SKY-CIRC`) appear in the same table format. The message
lists the cycle, its length, and a suggested module to break:

```text
Cycle: auth → models → auth
Length: 2
Suggested break: models
```

## Tuning Thresholds

All quality thresholds are configurable in `pyproject.toml`:

```toml
[tool.skylos]
complexity = 10       # Max cyclomatic complexity
nesting = 3           # Max nesting depth
max_args = 5          # Max function arguments
max_lines = 50        # Max function length
duplicate_strings = 3 # Max times a string literal can repeat
```

See [Configuration](/configuration) for the full list of options.
