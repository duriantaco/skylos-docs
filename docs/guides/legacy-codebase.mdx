---
title: "Tutorial: Clean Up a Legacy Codebase"
description: "Step-by-step guide to safely removing dead code from an existing project"
---

You've inherited a codebase. It's big, it's messy, and nobody knows what's actually used. This tutorial walks you through using Skylos to clean it up **safely**.

## Before You Start

:::warning
  **Prerequisites:**
  - Git repository with clean working tree
  - Test suite (even partial coverage helps)
  - 2-4 hours of uninterrupted time
:::


```bash
git status  # Should be clean
git checkout -b cleanup/dead-code-removal
```

---

## Phase 1: Assessment (30 min)

First, understand the scope of the problem.

### Step 1: Initial Scan

```bash
pip install skylos
skylos . --json -o baseline.json
```

### Step 2: Review the Numbers

```bash
skylos .
```

The summary near the top shows the counts:

```text
Unused functions: 47 Unused imports: 234 Unused params: 89 Unused vars: 56 ...
```

**Don't panic.** These numbers are normal for legacy codebases.

### Step 3: Categorize the Findings

```bash
# High-confidence findings (safe to act on)
skylos . --confidence 80 --json -o high-confidence.json

# Count them
cat high-confidence.json | python -c "import json,sys; d=json.load(sys.stdin); print(sum(len(v) for v in d.values() if isinstance(v,list)))"
```

**Start with high-confidence findings.** These are the safest to remove.

---

## Phase 2: Quick Wins (1 hour)

Remove obvious dead code that's safe to delete.

### Step 1: Unused Imports

Unused imports are usually the safest to remove. The exception is an import
kept for its side effects, such as registering a plugin.

```bash
# See unused imports, one per line
skylos . --confidence 90 --format concise | grep SKY-U002
```

```text
api/views.py:3  SKY-U002  unused import: json
models.py:1  SKY-U002  unused import: Optional
utils/helpers.py:5  SKY-U002  unused import: deprecated_lib
```

### Step 2: Preview Cleanup

Use `skylos clean` to preview Python import cleanup without editing files:

```bash
skylos clean . --dry-run --types import --confidence 90
```

The output is grouped by file and line:

```
Dry run: would remove 3 dead code items.

api/views.py
  L3 import json (95%)
models.py
  L1 import Optional (92%)
utils/helpers.py
  L5 import deprecated_lib (90%)
```

### Step 3: Apply Changes

```bash
# Remove matching imports without prompting
skylos clean . --apply --types import --confidence 90
```

### Step 4: Verify

```bash
# Run tests
pytest

# If tests pass, commit
git add -A
git commit -m "chore: remove unused imports (47 files)"
```

:::tip
  **Commit frequently.** Small commits are easier to revert if something breaks.
:::

## Phase 3: Dead Functions (1-2 hours)

Functions are riskier than imports. Proceed carefully.

### Step 1: List Candidates

```bash
skylos . --confidence 80 --format concise | grep SKY-U001
```

```text
api/legacy.py:45  SKY-U001  unused function: legacy_handler
utils/helpers.py:120  SKY-U001  unused function: unused_helper
models/validators.py:30  SKY-U001  unused function: old_validator
```

### Step 2: Investigate Before Deleting

For each function, check:

```bash
# Is it called dynamically?
grep -r "getattr.*legacy_handler" .
grep -r "'legacy_handler'" .
grep -r '"legacy_handler"' .

# Is it in a public API?
grep -r "from.*import.*legacy_handler" .

# Is it referenced in configs?
grep -r "legacy_handler" *.yaml *.json *.toml
```

### Step 3: Comment Out First (Safer)

```bash
skylos clean . --apply --comment-out --types function --confidence 80
```

This wraps the code in markers instead of deleting it:

```python
# SKYLOS DEADCODE START (lines 45-47)
# def legacy_handler():
#     """Old handler, replaced in v2."""
#     return None
# SKYLOS DEADCODE END
```

`skylos clean` edits Python files only.

### Step 4: Run Full Test Suite

```bash
pytest
# or your full CI command, e.g. make test
```

### Step 5: Verify in Staging

If tests pass, deploy to staging:

```bash
git add -A
git commit -m "chore: comment out potentially dead functions"
git push origin cleanup/dead-code-removal
# Deploy to staging
```

Monitor for a few days. If nothing breaks, convert comments to deletions.

### Step 6: Permanent Deletion

After staging validation:

```bash
# Find all marked dead code
grep -r "SKYLOS DEADCODE" . --include="*.py"

# Delete the commented lines (or do it manually)
# Then commit
git commit -am "chore: remove confirmed dead functions"
```

## Phase 4: Framework Code (30 min)

Framework code needs special attention due to implicit calling.

### Step 1: Lower Confidence Threshold

```bash
skylos . --confidence 50 --format concise | grep SKY-U001
```

You'll see more findings, but also more false positives.

### Step 2: Check Framework Patterns

For each finding, verify it's not:

```python
# Django view (called via URL routing)
def user_detail(request, pk):  # Check urls.py
    pass

# Flask route (called via decorator)
@app.route("/users")
def get_users():  # Skylos should catch this, but verify
    pass

# Celery task (called via .delay())
@celery.task
def process_job():  # Called asynchronously
    pass

# Signal receiver
@receiver(post_save)
def on_save():  # Called implicitly
    pass
```

### Step 3: Add Exclusions for False Positives

Mark the name as intentionally used:

```bash
skylos whitelist specific_false_positive_function --reason "called by the plugin loader"
```

This writes to `[tool.skylos.whitelist]` in `./pyproject.toml` (run it from
the folder that holds that file). `[tool.skylos] ignore` is for rule IDs such
as `SKY-L027`, not for function names.

Or inline:

```python
def framework_callback():  # skylos: ignore
    pass
```

## Phase 5: Quality Issues (Optional)

While you're cleaning up, address quality issues too.


```bash
skylos . --quality --format concise
```

```text
orders.py:45  SKY-Q301  Cyclomatic complexity is 23 (threshold: 10). Consider splitting branches.
validators.py:23  SKY-Q302  Nesting depth of 7 exceeds threshold of 3. Consider using early returns.
```

### Prioritize by Severity

Complexity findings top out at HIGH. A complexity number is not an exploitable
defect, so it is never CRITICAL.

| Severity | Action |
|----------|--------|
| HIGH | Fix soon (complexity 15 or more) |
| MEDIUM or lower | Add to backlog |

### Quick Complexity Fixes

```python
# Before: Complexity 15
def process(data):
    if data.valid:
        if data.type == "A":
            for item in data.items:
                if item.active:
                    # nested logic...

# After: Complexity 6 (extract + early return)
def process(data):
    if not data.valid:
        return None
    if data.type == "A":
        return process_type_a(data)
    return process_other(data)

def process_type_a(data):
    return [handle(item) for item in data.items if item.active]
```

## Phase 6: Set Up Prevention

Don't let dead code accumulate again.

### Pre-commit Hook

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/duriantaco/skylos
    rev: v5.1.1
    hooks:
      - id: skylos-scan
        args: [".", "--confidence", "80", "--danger"]
```

The `skylos-scan` hook reports findings but does not block the commit. Use the
CI gate below to block.

### CI Gate

```yaml
# .github/workflows/quality.yml
- name: Skylos Gate
  run: skylos . --danger --quality --ai-defects --gate
```

Dead code does not fail the gate unless you set a limit:

```toml
[tool.skylos.gate]
max_dead_code = 0
```

### Scheduled Cleanup

```yaml
# .github/workflows/cleanup-reminder.yml
name: Monthly Cleanup Reminder
on:
  schedule:
    - cron: '0 9 1 * *'  # First of each month

jobs:
  report:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install skylos
      - run: |
          skylos . --json -o report.json
          skylos . --gate --summary --force
```

```
□ Create cleanup branch
□ Run baseline scan
□ Remove unused imports (commit)
□ Comment out dead functions (commit)
□ Run tests
□ Deploy to staging
□ Monitor for 3-5 days
□ Convert comments to deletions (commit)
□ Address high-severity complexity (commit)
□ Set up pre-commit hook
□ Set up CI gate
```

## Troubleshooting


  <details>
<summary>Tests fail after removing 'dead' code</summary>

    The code wasn't dead—it was called dynamically or by tests.
    
    ```bash
    # Revert
    git checkout -- path/to/file.py
    
    # Add suppression
    def not_actually_dead():  # skylos: ignore
        pass
    ```
  </details>
  
  <details>
<summary>Too many findings to review</summary>

    Raise the confidence threshold:

    ```bash
    skylos . --confidence 90
    ```
    
    Focus on the highest-confidence items first.
  </details>
  
  <details>
<summary>Framework code keeps getting flagged</summary>

    Skylos might not recognize your specific framework pattern. Declare it as an
    entry point in config, so every handler with that decorator counts as used:

    ```toml
    [[tool.skylos.dead_code.entrypoints]]
    decorators = ["custom_framework_decorator"]
    reason = "Registered by our framework at startup"
    ```

    Or suppress one handler inline:

    ```python
    @custom_framework_decorator
    def handler():  # skylos: ignore
        pass
    ```
  </details>
  
  <details>
<summary>Production broke after removing code</summary>

    If code was called dynamically and tests didn't catch it:
    
    1. Revert immediately: `git revert HEAD`
    2. Add monitoring for that code path
    3. Add suppression: `# skylos: ignore` or `skylos whitelist NAME`
    4. Consider adding a test for the dynamic call
  </details>
