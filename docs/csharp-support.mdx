---
title: "C# Support"
description: "C# dead code and selected security analysis support in Skylos."
---

Skylos analyzes C# source with lightweight symbol extraction for dead code and
selected security checks. It is designed to make `.cs` files visible in the
normal Skylos workflow without requiring MSBuild, Roslyn, or the .NET SDK.

## File Coverage

| Area | Support |
|:---|:---|
| Extensions | `.cs` |
| Dead code | Partial: classes, methods, and direct references |
| Security | Selected ASP.NET/request input to process, SQL, HTTP, redirect, and filesystem sinks |
| Quality | Unreachable code after `return`, `throw`, `break`, or `continue` (`SKY-UC002`) |
| Secrets | `.cs` files with `--secrets` or `-a` |
| Dependencies | Direct NuGet `PackageReference` entries in `.csproj` with `--sca` |

## Dead Code Detection

C# analysis recognizes class and method declarations, imports, and direct method
references. Findings are normalized into the same report shape as other
languages, so C# files appear in CLI, JSON, SARIF, MCP, and Cloud output.

Findings are conservative. Unreferenced public types and methods are
low-confidence candidates. Library APIs, protected members, and known framework
entry points are treated as reachable. Whole-file reachability is not
implemented.

```bash
skylos .
```

## Security Scope

C# security checks track request-like or user-controlled values into selected
high-risk sinks:

- process execution such as `Process.Start` and `ProcessStartInfo`
- SQL command construction such as `SqlCommand`, `DbCommand`, and raw SQL APIs
- HTTP requests such as `HttpClient.GetAsync`, `SendAsync`, and `WebRequest`
- filesystem APIs under `File` and `Directory`
- ASP.NET redirect sinks

```bash
skylos . --danger
```

## Limitations

C# support is intentionally lightweight today. Skylos does not run MSBuild,
Roslyn analyzers, NuGet restore, or .NET type resolution. Unreachable-code
detection is direct-block only, not full control flow. C# has no inline
suppression comment. `skylos verify` reports C# API proof as unsupported.
Dependency scanning checks only exact `[version]` pins; ordinary NuGet versions
are minimum bounds, so their vulnerability status stays unknown. Use `dotnet build`,
`dotnet test`, Roslyn analyzers, and project-specific security checks alongside
Skylos when you need compiler-level validation.
