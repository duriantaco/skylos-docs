## What is the Skylos MCP Server?

The Skylos MCP server exposes Skylos's static analysis engine as a set of tools that AI assistants can call directly. Instead of copy-pasting code into a chat window, you can ask Claude (or any MCP-compatible client) to scan your project, and it runs the real Skylos engine on your machine.

```
You: "Scan my project for security issues"
Claude -> calls security_scan("./my-project")
     -> Skylos runs taint analysis, dangerous-call detection, etc.
     -> Returns structured findings
Claude: "I found 3 issues: SQL injection on line 42, SSRF on line 87, ..."
```

This is not a summarizer or wrapper: it runs the same analysis as `skylos . --danger` on the CLI.

:::info API key
Without an API key, only `analyze` works: five calls per rolling 24-hour window, without credits.
Every other tool needs a free Skylos API key. Authenticated MCP scans run locally but can use
Skylos Cloud credits; see the prices below. Local CLI scans need no key and use no credits.
See [Authentication (API Key)](#authentication-api-key).
:::

## What Skylos Detects

Coverage varies by language; see [Language Support](/language-support). Through MCP, your AI assistant gets access to:

| Capability | What It Finds | Rule IDs |
|------------|---------------|----------|
| **Dead Code** | Unused functions, imports, classes, variables | SKY-U001–U004 |
| **Security** | SQL injection, XSS, SSRF, command injection, path traversal, CORS, JWT, mass assignment, MCP server vulnerabilities | SKY-D201–D244 |
| **Secrets** | Hardcoded API keys (AWS, Stripe, OpenAI, GitHub, Slack, etc.) | SKY-S101 |
| **Quality** | Cyclomatic complexity, deep nesting, async blocking, god classes | SKY-Q301–Q501 |
| **Logic Bugs** | Mutable defaults, bare except, dangerous comparisons, inconsistent returns | SKY-L001–L006 |
| **Supply Chain** | Hallucinated dependencies, undeclared imports, real packages called with invented APIs, and npm/Go versions that do not exist | SKY-D222–D225 |
| **Remediation** | Plans or applies LLM-generated fixes, then re-scans to confirm each finding is gone | — |

For the full rules reference, see [Rules Reference](/rules-reference).

## Setup

### Prerequisites

```bash
pip install skylos
```

The `skylos mcp` command needs Skylos 4.45.0 or newer. On older versions, use `python -m skylos_mcp.server` in place of `skylos mcp`.

### Claude Desktop

Add to your Claude Desktop config:

- **macOS**: `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Linux**: `~/.config/claude/claude_desktop_config.json`
- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "skylos": {
      "command": "skylos",
      "args": ["mcp"],
      "env": {
        "SKYLOS_API_KEY": "your-api-key-here"
      }
    }
  }
}
```

Restart Claude Desktop. You should see "skylos" listed in the tools menu.

### Cursor / VS Code with MCP

If your editor supports MCP servers, add the same configuration to your editor's MCP settings. The command is the same:

```bash
skylos mcp
```

### Virtual Environment

If Skylos is installed in a virtual environment, point to the `skylos` command in that venv:

```json
{
  "mcpServers": {
    "skylos": {
      "command": "/path/to/venv/bin/skylos",
      "args": ["mcp"]
    }
  }
}
```

### Authentication (API Key)

Every tool except `analyze` needs an API key. Create one in Skylos Cloud at [skylos.dev/dashboard/settings](https://skylos.dev/dashboard/settings) (a Free account works) and pass it to the server as `SKYLOS_API_KEY`, as in the Claude Desktop example above.

**Without an API key**, only `analyze` works, five calls per rolling 24-hour window. Every other tool returns an authentication error. The local CLI needs no key: `skylos verify <file>` and `skylos agent install-hooks` run without an account.

**With an API key**, tools are subject to your balance, rate limit and any required LLM provider
configuration. The current standard Skylos Cloud prices are:

| Tool | Credits | Notes |
|------|---------|-------|
| `analyze` | 1 | Dead code. Free without a key within the five-call limit |
| `security_scan` | 2 | Security findings |
| `quality_check` | 1 | Quality and logic findings |
| `architecture_check` | 1 | Coupling, cohesion and circular dependencies |
| `health_score` | 1 | Overall grade across dead code, security, secrets and quality |
| `secrets_scan` | 1 | Hard-coded secrets (values redacted) |
| `verify_change` | None | AI-code trust findings for a changed file or line range |
| `validate_code_change` | None | Checks a unified diff for security regressions and made-up dependencies |
| `verify_agent` | None | Deterministic AI-agent guardrail verification |
| `provenance_scan` | 2 | Attributes changed files to AI agents, bots or humans from Git history |
| `generate_fix` | None | Removal patch for dead code |
| `learn_triage` / `get_triage_suggestions` | None | Records and suggests triage decisions |
| `get_security_context` | None | Summary of frameworks, auth, headers and policy |
| `verify_dead_code` | None | LLM review of dead-code findings; needs your own LLM provider key |
| `remediate` | **10** | LLM-generated fixes; needs your own LLM provider key |

Analysis runs on your machine. Authenticated calls use Skylos Cloud to validate the key and
deduct credits for priced tools. Cloud configures the prices; check your balance with
`skylos credits`. A Free workspace can use retained trial credits, but a priced call can fail
when its balance is too low. LLM-provider charges are separate from Skylos credits.

**Enterprise plans** have unlimited credits.

See [Billing & Credits](/billing) for pricing and credit packs.

### Rate Limits

| Plan | Rate Limit |
|------|-----------|
| No API key | 5 calls per rolling 24 hours (`analyze` only) |
| Free | 50 calls/hour |
| Workspace | 500 calls/hour |
| Enterprise | 5,000 calls/hour |

### Custom Results Directory

By default, analysis results are stored in `~/.skylos/mcp_results/`. Override with:

```json
{
  "mcpServers": {
    "skylos": {
      "command": "skylos",
      "args": ["mcp"],
      "env": {
        "SKYLOS_API_KEY": "your-api-key",
        "SKYLOS_MCP_RESULTS_DIR": "/path/to/results"
      }
    }
  }
}
```

## Available Tools

### `analyze`

Scans for dead code: unused functions, imports, classes, variables, and parameters. This is the only tool that works without an API key (five calls per rolling 24 hours).

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `path` | string | required | Path to scan |
| `confidence` | int | 60 | Confidence threshold (0–100). Lower = more findings, higher = fewer false positives |
| `exclude_folders` | list | auto | Folders to skip (defaults: `__pycache__`, `.git`, `venv`, etc.) |

**Example prompt**: "Find all dead code in my project"

**Returns**: Unused functions, imports, classes, variables, parameters, and empty files with confidence scores.

---

### `security_scan`

Runs the security scanner: taint analysis, dangerous function detection, and vulnerability checks.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `path` | string | required | Path to scan |
| `confidence` | int | 60 | Confidence threshold |
| `exclude_folders` | list | auto | Folders to skip |

**Example prompt**: "Scan src/ for security vulnerabilities"

**Returns**: All danger findings (SKY-D rules) with file, line, severity, and description.

**What it detects**:
- SQL injection (taint tracking from request params to `cursor.execute()`)
- Command injection (`os.system()`, `subprocess(shell=True)` with user input)
- SSRF (tainted URLs in `requests.get()`, `httpx`, `urllib`)
- Path traversal (user input in `open()`, `Path()`)
- XSS (`mark_safe()`, disabled autoescape, HTML string building)
- Dangerous calls (`eval`, `exec`, `pickle`, `yaml.load`)
- Weak cryptography (`md5`, `sha1`)
- CORS misconfiguration, JWT vulnerabilities, mass assignment
- MCP server security issues (D240–D244)
- Supply chain risks (hallucinated/undeclared dependencies)

---

### `quality_check`

Analyzes code quality: complexity, nesting, structure, and logic patterns.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `path` | string | required | Path to scan |
| `confidence` | int | 60 | Confidence threshold |
| `exclude_folders` | list | auto | Folders to skip |

**Example prompt**: "Check the code quality of my utils/ directory"

**Returns**: Quality findings (SKY-Q, SKY-C, SKY-L, SKY-P rules), circular dependency analysis, and custom rule violations.

---

### `secrets_scan`

Detects hardcoded credentials and sensitive data.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `path` | string | required | Path to scan |
| `confidence` | int | 60 | Confidence threshold |
| `exclude_folders` | list | auto | Folders to skip |

**Example prompt**: "Find any hardcoded secrets in my project"

**Returns**: All SKY-S101 findings (API keys, tokens, passwords, and private keys) with the file, line number, and detected provider. Secret values are redacted.

**Scanned file types**: `.py`, `.pyi`, `.pyw`, `.env`, `.yaml`, `.yml`, `.json`, `.toml`, `.ini`, `.cfg`, `.conf`, `.ts`, `.tsx`, `.js`, `.jsx`, `.go`, `.java`, `.php`, `.rs`

**Detected providers**: AWS, Stripe, GitHub, GitLab, Slack, Google, SendGrid, Twilio, OpenAI, Anthropic, and generic high-entropy strings.

---

### `verify_change`

Verifies a changed file or line range for AI-code trust findings. This is the
MCP equivalent of `skylos verify`, intended for coding agents to call after an
edit before showing the change to a human.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `path` | string | `"."` | File or project root to verify |
| `file` | string | null | Target file when `path` is a project root |
| `line_range` | string | null | Changed range such as `"40:75"` |
| `confidence` | int | 60 | Confidence threshold |
| `project_context` | bool | false | Scan the project root and filter to `file` |
| `include_dependency_hallucinations` | bool | true | Include package metadata checks for hallucinated dependencies and versions |
| `contract_path` | string | null | Path to an AI hallucination contract, equivalent to `skylos verify . --contract PATH` |
| `exclude_folders` | string | null | Comma-separated folders to exclude |

**Example prompt**: "Verify the change I just made to `src/app.py` lines 40 to 75."

**Returns**: Versioned JSON with `tool: "verify_change"`, `status`, target
metadata, and only AI-code findings such as hallucinated references,
incomplete generation, stale references, disabled controls, dependency
hallucinations, API signature hallucinations, weakened assertions, and
contract-required route guardrails. AI-defect findings use `category: "ai_defect"`.
Contract-backed findings can include `contract_id`, `contract_clause`,
`contract_path`, and `contract_reason`.

Dependency checks are diff-aware: if a raw diff adds both a Python import and
the matching PyPI declaration in `requirements*.txt` or `pyproject.toml`, the
import is treated as declared. For `package.json`, registry checks only inspect
entries inside dependency sections such as `dependencies`, `devDependencies`,
`peerDependencies`, and `optionalDependencies`.

---

### `verify_agent`

Statically verifies AI-agent guardrails before deployment. It inventories LLM integrations, runs the same deterministic defense checks as `skylos defend`, and returns defense/ops scores, failed checks with remediation, OWASP coverage summary, an optional gate verdict, and an attestation digest.

```json
{
  "path": ".",
  "fail_on": "critical",
  "owasp_framework": "agentic"
}
```

**Returns**: Compact JSON with `tool: "verify_agent"`, `defense_score`, `ops_score`, `failed_checks`, `owasp`, `gate`, and `attestation`. The verification is deterministic static analysis, not another model reviewing the code.

---

### `remediate`

Plans or applies LLM-generated fixes for findings. Over MCP it does not run your tests: review the plan, and run your tests yourself after applying fixes. Costs 10 credits per call.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `path` | string | required | Path to scan and fix |
| `max_fixes` | int | 5 | Maximum number of fixes to attempt |
| `dry_run` | bool | true | If true, shows plan without applying. Set to false to apply fixes. |
| `model` | string | "gpt-4.1" | LLM model for fix generation |
| `test_cmd` | string | null | Not supported over MCP; passing it returns an error |
| `severity` | string | null | Minimum severity filter: `critical`, `high`, `medium`, `low` |

**Example prompt**: "Fix the top 3 security issues in my project, but don't apply yet. Show me the plan."

**Returns**: Remediation plan with a status for each finding (for example `fixed`, `skipped`, `failed` or `not_resolved`). After applying a fix, Skylos re-scans the file and reverts the fix if the finding is still there. Security remediation can include generated regression-test proof metadata, such as the rule family, source file, and candidate test file.

:::caution
Set `dry_run=false` only when you're ready to modify files. Skylos does not run your tests over MCP, so run them yourself before you keep the changes.
:::

**Safety guardrails**:
- Dry run by default: nothing changes unless you explicitly set `dry_run=false`
- Low-confidence fixes are skipped
- After applying a fix, Skylos re-scans to confirm the finding is resolved, and reverts the fix if it is not
- For supported security findings such as `SKY-D211`, Skylos can attach a targeted regression-test candidate after the fix is verified
- Maximum fixes capped at `max_fixes` to prevent runaway changes

:::note
The `remediate` tool requires an LLM API key. Set `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` in the MCP server's environment, or configure keys via `skylos key`.
:::

## Available Resources

Resources provide access to stored analysis results.

| Resource URI | Description |
|-------------|-------------|
| `skylos://results/latest` | The most recent analysis result |
| `skylos://results/{run_id}` | A specific analysis result by run ID |
| `skylos://results` | List all stored analysis runs |

Every tool call returns a `_run_id` in its response. Use this ID to retrieve the full result later:

```
You: "What was the last security scan result?"
Claude → reads skylos://results/latest
```

Results are persisted to `~/.skylos/mcp_results/` so they survive server restarts.

## Example Conversations

### Security audit

```
You: "Run a security scan on my project at ./backend"

Claude: I'll scan your backend for security vulnerabilities.
[Calls security_scan(path="./backend")]

I found 5 security issues:
1. CRITICAL: SQL injection on line 42 of api/users.py (SKY-D211)
2. HIGH: Path traversal on line 87 of api/files.py (SKY-D215)
3. HIGH: CORS misconfiguration in config.py (SKY-D231)
4. MEDIUM: Weak hash (MD5) on line 15 of utils/crypto.py (SKY-D207)
5. MEDIUM: Undeclared dependency 'httpx' (SKY-D223)
```

### Finding dead code

```
You: "Find unused code in src/ with high confidence only"

Claude: I'll scan for dead code with a high confidence threshold.
[Calls analyze(path="src/", confidence=80)]

Found 12 unused items:
- 4 unused functions (90%+ confidence)
- 6 unused imports
- 2 unused classes
```

### Remediation workflow

```
You: "Fix the critical security issues but show me the plan first"

Claude: I'll generate a remediation plan for critical issues.
[Calls remediate(path="./backend", severity="critical", dry_run=true)]

Remediation plan:
1. SKY-D211 (SQL injection, api/users.py:42) → Will parameterize the query
2. SKY-D204 (pickle.load, data/loader.py:15) → Will replace with json.loads

Ready to apply? Say "apply the fixes" to proceed.

You: "Apply the fixes"
[Calls remediate(path="./backend", severity="critical", dry_run=false, max_fixes=2)]

Results:
- api/users.py: Fixed (finding resolved on re-scan)
- data/loader.py: Fixed (finding resolved on re-scan)

Run your test suite before keeping these changes.
```

### Checking for secrets before deploy

```
You: "Any hardcoded secrets in the codebase?"

Claude: Let me scan for secrets.
[Calls secrets_scan(path=".")]

Found 2 secrets:
1. AWS access key (AKIA...) in config/aws.py:8
2. Stripe key (sk_live_...) in billing/checkout.py:23

Recommendation: Move these to environment variables or a secrets manager.
```

## How It Works

```
┌─────────────────────┐      stdio/SSE      ┌──────────────────────┐
│  Claude Desktop /   │ ◄──────────────────► │  skylos mcp          │
│  Cursor / Any MCP   │    MCP Protocol      │  (FastMCP)           │
│  Client             │                      │                      │
└─────────────────────┘                      └──────────┬───────────┘
                                                        │
                                                        ▼
                                             ┌──────────────────────┐
                                             │  skylos.analyzer     │
                                             │  (Core Engine)       │
                                             ├──────────────────────┤
                                             │  AST parsing         │
                                             │  Taint analysis      │
                                             │  Pattern matching    │
                                             │  Tree-sitter (TS)    │
                                             │  Secrets scanning    │
                                             │  Quality rules       │
                                             │  Dependency checks   │
                                             └──────────┬───────────┘
                                                        │
                                             ┌──────────▼───────────┐
                                             │  Results Cache       │
                                             │  ~/.skylos/          │
                                             │  mcp_results/        │
                                             └──────────────────────┘
```

1. **MCP client** (Claude Desktop, Cursor, etc.) connects to the Skylos server via stdio
2. **Tool calls** are routed to Skylos's core `analyzer.analyze()` function, the same engine used by the CLI
3. **Results** are stored in-memory and on disk (`~/.skylos/mcp_results/`) for later retrieval via resources
4. **Remediation** uses Skylos's LLM orchestrator to generate and apply fixes, then re-scans to confirm each finding is resolved. It does not run tests over MCP.

Analysis runs on your machine; see [Privacy](#privacy) for the network calls the server makes.

## Troubleshooting

### Server not appearing in Claude Desktop

1. Verify the config file path is correct for your OS
2. Check that `skylos mcp` starts from your terminal (it waits for MCP messages on stdin; stop it with Ctrl+C)
3. Restart Claude Desktop after editing the config
4. Check Claude Desktop logs for connection errors

### "Command not found" or "Module not found" error

Skylos must be installed where the config points:

```bash
# Check which skylos
which skylos

# Install skylos there
python -m pip install skylos

# Or use the absolute path in the config
/Users/you/venv/bin/skylos mcp
```

### A tool returns an authentication error

Every tool except `analyze` needs `SKYLOS_API_KEY` in the MCP server's environment. Create a key at [skylos.dev/dashboard/settings](https://skylos.dev/dashboard/settings) and add it to the `env` block of the server config.

### Analysis returns empty results

- Check that the `path` parameter points to a valid directory with Python/TypeScript files
- Lower the `confidence` threshold (e.g., `confidence=40`) to see more findings
- Verify the directory isn't excluded by default (check `--list-default-excludes`)

### Remediate tool fails

- Ensure an LLM API key is set: `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`
- Check that the model name is valid (e.g., `gpt-4.1`, `claude-sonnet-4-20250514`)
- For local LLMs, configure `SKYLOS_LLM_BASE_URL` in the environment
- Check your credit balance with `skylos credits`; `remediate` costs 10 credits

## Privacy

- **Source code** stays on your machine for every scan tool. Results are stored locally at `~/.skylos/mcp_results/`.
- **Skylos Cloud:** with `SKYLOS_API_KEY` set, the server contacts skylos.dev to validate the key and to deduct credits for tools that use them.
- **Package registries:** dependency checks send package names to PyPI, npm and the Go module proxy.
- **LLM providers:** `remediate` and `verify_dead_code` send code snippets to your configured LLM provider (OpenAI, Anthropic, or local). Use a local LLM (Ollama) to keep them on your machine.
- **Secrets scanning:** detected secret values are redacted in results.
