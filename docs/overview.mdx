## Ship Cleaner, Safer Code

Skylos is an open-source static analysis tool and CI/CD PR gate. It combines
dead code detection, security scanning, secrets detection, quality checks, and
AI-generated code guardrails in one local-first CLI.

Use it when you want to:

- remove unused code without breaking framework entrypoints
- catch exploitable flows before they reach `main`
- detect hardcoded secrets and risky CI/CD or edge-device configuration
- enforce standards-backed coding practices for typing, framework routes, and repo policy
- keep pull requests focused on new issues instead of legacy noise
- review AI-assisted edits for missing controls, phantom helpers, and unfinished code

## Core Workflows

| Workflow | Command | What It Does |
|:---|:---|:---|
| Dead code scan | `skylos .` | finds unused functions, classes, imports, files, and entrypoints |
| Main source audit | `skylos . -a` | adds security, secrets, config, quality, AI-defect, and dependency checks |
| Changed-code review | `skylos . -a --diff origin/main` | focuses on lines touched by a PR |
| Change map for review | `skylos done map --base origin/main` | lists each changed Python or TypeScript/JavaScript function with old and new code, callers, removed security checks and what to read first; see [Change Map](/change-map) |
| AI-code verification | `skylos verify` | scans the selected source target; separately compares supported Python working changes with Git HEAD |
| Built GPU artifact preflight | `skylos preflight build/app` | compares exact local artifact evidence with the declared GPU fleet; OCI is `UNKNOWN` in the CLI |
| Container vulnerability scan | `skylos image scan IMAGE@sha256:<digest> --platform linux/amd64` | uses separately installed Trivy plus registry network access; findings gate only with `--fail-on` |
| Combined repo report | `skylos suite` | runs static, debt, defense, and provenance checks; findings are report-only |
| Dead-code cleanup | `skylos clean --dry-run` | previews Python import/function edits without writing files |
| CI gate | `skylos cicd init` | sets up the pull request gate for GitHub Actions, GitLab CI, Jenkins, Bitbucket Pipelines, Azure Pipelines or CircleCI |
| Pre-deployment agent verification | `skylos defend . --format md` | reports guardrails for recognized Python and TypeScript/JavaScript integrations; gating is opt-in |
| Runtime agent behavior test | `skylos agent test --allow-contract-endpoint` | checks responses, tool selection, refusals, and source IDs against a contract |
| Agent review | `skylos agent scan .` | optional LLM-assisted review and fix suggestions |

`verify` scans source and models supported Python working changes, `preflight`
statically reads a local built GPU artifact, and `image scan` asks Trivy to
scan a remote registry image. See the [CLI
Reference](/cli-reference#choose-the-command-by-its-input) for the command
chooser.

## How Skylos Is Different

Skylos is not a replacement for every specialized scanner. It is a local-first
repo and PR checker that puts several common review checks behind one CLI.

### Framework-Aware Dead Code

Generic unused-code tools often flag route handlers, pytest fixtures, Pydantic
models, serializers, package entrypoints, and plugin hooks. Skylos models common
framework and language patterns so dynamic code is less likely to appear as
dead.

Skylos understands patterns from ecosystems such as FastAPI, Django, Flask,
pytest, SQLAlchemy, Next.js (App/Pages Router files and metadata routes),
React, Laravel (auto-discovered commands, listeners, components, factories,
seeders), Drupal (classes named in an extension's YAML, discovered plugins, OOP
hooks, procedural hooks in `.module`/`.install`/`.inc`/`.theme` files,
post-update functions), tool config files, package exports and entrypoints,
and plugin loading.

### Data-Flow Security Scanning

Skylos does not only look for dangerous function names. It tracks untrusted
input through assignments, parameters, string construction, and framework
handlers into sinks such as SQL execution, HTTP clients, filesystem paths,
template rendering, subprocess execution, and deserialization.

### PR-Native Enforcement

Skylos can run locally or in CI. Diff-aware scans keep new work separate from
legacy findings, CI thresholds gate merges, baselines hold existing findings,
and GitHub annotations put results where reviewers already work.
Standards-backed quality checks can start as advisory CI signals before
becoming hard merge gates.

### Local-First By Default

Core static analysis runs on your machine without an API key or source upload,
and does not call an LLM. Cloud upload, LLM-assisted review, and remediation
are optional. Dependency checks can query OSV or package registries, and
direct image scanning contacts a registry through Trivy. See
[What leaves your machine](https://github.com/duriantaco/skylos/blob/main/docs/privacy-and-network.md).

### AI-Assisted Change Review

Skylos checks for removed validation, auth, logging, CSRF, rate limiting,
timeouts, real-package API hallucinations, and other guardrails in generated
or edited code.

### Agent-Loop Verification

`skylos verify` and the MCP `verify_change` tool use a versioned result schema
for AI-code trust, security, and secret findings, so coding agents can
self-correct before a human sees the change. The CLI renders a human report on
a terminal and JSON when redirected or written with `-o`.

### Evidence-Backed AI Defects

`--ai-defects` and full scans put strict AI-code failure checks under
`ai_defects`, including phantom references, fake package APIs, nonexistent
packages, impossible dependency versions, and weakened test assertions. The
category/tag is `ai_defect`; several rules intentionally keep historical
`SKY-L` or `SKY-D` IDs for suppression and baseline compatibility, while new
AI-defect-only checks use `SKY-A`.

### Verification-Backed Remediation

Security fixes are checked by re-running analysis, and supported findings can
include targeted regression-test proof metadata.

### Project-Specific Rules

Add local YAML rules and extend prompt, credential, sensitive-file, and timeout
dictionaries from config. See [Configuration](/configuration) and
[`skylos rules`](/cli-reference#skylos-rules).

### One Command Surface

Dead code, security, secrets, dependency, quality, technical debt, agent
review, and pre-deployment agent verification commands share the same CLI.

## Language Support

| Language | Dead Code | Security | Quality |
|:---|:---:|:---:|:---:|
| Python | Yes | Yes | Yes |
| TypeScript / JavaScript | Yes | Yes | Yes |
| Java | Yes | Yes | Yes |
| Go | Yes | Partial | Partial |
| PHP | Yes | Yes | No |
| Rust | Experimental | Partial | Partial |
| Ruby | Partial | Partial | No |
| Dart | Yes | Partial | No |
| C# | Partial | Partial | Partial |
| C++ | Partial | No | No |
| Kotlin | Partial | Partial | No |
| Swift | Partial | No | No |
| Shell | No | Partial | No |
| Deployment config | No | Partial | No |

Go dead-code and security checks need the native `skylos-go` engine, Dart
needs the `skylos[dart]` extra, and Rust dead code is hidden below the default
confidence threshold.

For detailed scanner scope, see [Language Support](/language-support) and
[Rules Reference](/rules-reference).
