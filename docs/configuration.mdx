---
title: "Configuration"
description: "Configure Skylos via pyproject.toml. Set exclusions, confidence thresholds, quality gate rules, and framework-specific settings."
---

Skylos reads settings from `[tool.skylos]` in `pyproject.toml`, or from a
`skylos.toml` or `.skylos.toml` file. Run `skylos init` to add a full
`[tool.skylos]` template to `pyproject.toml`, or add the section yourself.

In `skylos.toml` and `.skylos.toml`, keys can sit at the top level or under
`[skylos]` or `[tool.skylos]`.

## Configuration File
```toml
[tool.skylos]
# Quality thresholds
complexity = 10
nesting = 3
max_args = 5
max_lines = 50
duplicate_strings = 3

# Rules to ignore (by rule ID)
ignore = []

# Extra folders or globs to skip
exclude = []

[tool.skylos.whitelist]
# Glob patterns to ignore as unused
names = [
    "handle_*",
    "visit_*",
    "*Plugin",
]

[tool.skylos.whitelist.documented]
# Patterns with reasons (recommended for teams)
"dark_logic" = "Called via globals() string manipulation"
"BasePlugin" = "Discovered via __subclasses__()"

[tool.skylos.whitelist.temporary]
# Temporary whitelist - warns when expired
"legacy_handler" = { reason = "Migration - JIRA-123", expires = "2026-03-01" }

[tool.skylos.overrides."src/plugins/*"]
# Per-path whitelist rules
whitelist = ["*Plugin", "*Handler"]

[tool.skylos.dead_code]
entrypoints = []

[[tool.skylos.dead_code.entrypoints]]
type = "method"
name = ["create", "pre_hook", "post_hook"]
parent = { name = "Main", base_classes = ["Application"] }
path = "src/**"
reason = "project framework lifecycle hook"

[tool.skylos.languages.typescript]
# Language-specific complexity limit
complexity = 15

[tool.skylos.languages.java]
complexity = 12

[tool.skylos.gate]
# Quality gate settings
max_high = 5
max_security = 10
max_reliability = 0
max_quality = 10
strict = false

[tool.skylos.contribution]
# Off by default. Stores structural accept/dismiss/learn signals locally only.
collect_local_signals = false
contribute_public_corpus = false
structural_signatures_only = true
include_source = false
```

## Configuration Options

### Quality Thresholds

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `complexity` | int | `10` | Maximum cyclomatic complexity before flagging a function |
| `nesting` | int | `3` | Maximum nesting depth before flagging |
| `max_args` | int | `5` | Maximum function arguments before flagging |
| `max_lines` | int | `50` | Maximum function length in lines |

### Analysis Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `ignore` | list | `[]` | List of rule IDs to suppress (e.g., `["SKY-L002", "SKY-Q301"]`) |
| `exclude` | list | `[]` | Folders or globs to skip, added to the default excludes |
| `include_generated` | bool | `false` | Also scan migrations, minified files and vendored files |
| `addopts` | string or list | none | Default scan flags added to every `skylos PATH` run, for example `"--danger --secrets"`. Only an allow-listed set of flags is accepted |
| `security_enabled`, `secrets_enabled`, `quality_enabled`, `ai_defects_enabled`, `sca_enabled` | bool | `false` | Turn that check on when you pass no check flag |
| `root` | bool | `false` | Stop reading config files from parent folders |
| `duplicate_strings` | int | `3` | Repeats before SKY-L027 flags a string |
| `god_file_max_lines`, `god_file_max_definitions`, `god_file_max_top_level_definitions` | int | `500`, `40`, `25` | Limits for SKY-Q502 (god file) |
| `check_circular` | bool | `true` | Report circular imports |
| `typing_coverage_advice` | bool | `false` | Show type-annotation coverage advice (SKY-T101, SKY-T102) |
| `license_deny`, `license_allow`, `license_exceptions`, `license_severity` | list / string | none | Dependency license policy. See [Dependencies and Supply Chain](./supply-chain#license-policy) |

LLM commands take the model from `--model` or the provider settings, not from
config. See [AI Features](./ai-features).

### Contribution Signals

The `[tool.skylos.contribution]` section controls AI-code defect signal capture.
It is explicit, opt-in, and off by default.

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `collect_local_signals` | bool | `false` | Record local structural accept/dismiss/learn events |
| `contribute_public_corpus` | bool | `false` | Reserved for public corpus contribution; keep disabled unless you explicitly opt in |
| `structural_signatures_only` | bool | `true` | Store rule/category/severity/file extension/line bucket/hashes instead of source text |
| `include_source` | bool | `false` | Always sanitized to `false`; raw source is not captured |

When local signal capture is enabled, Skylos stores bounded local events at:

```text
.skylos/contribution/events.json
```

Events are generated from agent-service accept, dismiss, and learn actions.
They include structural hashes and message hashes, not raw code. The file is
local project state and should normally be gitignored.

```toml
[tool.skylos.contribution]
collect_local_signals = true
contribute_public_corpus = false
structural_signatures_only = true
include_source = false
```

### Gate Configuration

The `[tool.skylos.gate]` section controls the quality gate behavior when using `--gate`:

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `max_high` | int | `5` | Maximum allowed high-severity findings |
| `max_security` | int | `10` | Maximum allowed security findings |
| `max_reliability` | int | `0` | Maximum allowed deployment/runtime Reliability findings; counted separately from `max_security` |
| `max_quality` | int | `10` | Maximum allowed quality findings |
| `max_ai_defects` | int | same as `max_quality` | Maximum allowed AI-defect findings |
| `block_ai_defect_severities` | list | `["CRITICAL"]` | One AI defect at these severities fails the gate |
| `max_dependency_vulnerabilities` | int | `0` | Maximum allowed dependency CVE findings |
| `max_dead_code` | int | no limit | Maximum allowed dead-code findings |
| `rules` | list | `[]` | Advice-only rule IDs to count in the gate, for example `["SKY-Q302"]` |
| `strict` | bool | `false` | When `true`, a failed gate never asks "Continue anyway?" |

Any critical security finding and any secret always fail the gate.
`fail_on_critical`, `max_critical` and `max_secrets` cannot relax that.

`[tool.skylos.gate.coverage]` controls incomplete scans: `require_complete`,
`required` (for example `["sca", "custom_rules"]`) and
`require_resolved_versions`.

Do not set `require_defend` or `min_defend_score` under
`[tool.skylos.gate.agent]`. Today the gate never reads `skylos defend`
results, so either key fails the gate with "no defense data available". To
gate on guardrails, run `skylos defend . --fail-on critical --min-score 70` as
its own CI step.

Release Reliability findings have their own JSON bucket, count, and gate
threshold. See [Release Reliability](./release-reliability) for the Kubernetes
and GPU rule contracts.

## Whitelist Configuration

Suppress false positives permanently without cluttering your code with inline comments.

### CLI Commands
```bash
# Add a glob pattern
skylos whitelist 'handle_*'

# Add with reason (recommended for teams)
skylos whitelist dark_logic --reason "Called via globals() in dispatcher"

# View current whitelist
skylos whitelist --show
```

`skylos whitelist` edits `pyproject.toml` in the current folder only. Run it
from the folder that holds that file. It does not edit `skylos.toml`, and with
no `pyproject.toml` it prints "No pyproject.toml found" and changes nothing.

### Whitelist Sections

#### `[tool.skylos.whitelist]`

Simple glob patterns for names to ignore:
```toml
[tool.skylos.whitelist]
names = [
    "handle_*",      # Event handlers called via getattr
    "visit_*",       # AST visitor methods
    "*Plugin",       # Plugin classes discovered via __subclasses__
    "*_callback",    # Callback functions
]
```

#### `[tool.skylos.whitelist.documented]`

Patterns with reasons - shows up in `skylos whitelist --show` and helps teams understand why something is whitelisted:
```toml
[tool.skylos.whitelist.documented]
"dark_logic" = "Called via globals() string manipulation in trigger_blindspots()"
"BasePlugin" = "Discovered via __subclasses__() at runtime"
"legacy_api" = "Called by external service - do not remove"
```

#### `[tool.skylos.whitelist.temporary]`

Patterns with expiration dates. After the `expires` date the entry stops hiding
findings, so they are reported again. Write the date as `YYYY-MM-DD`:
```toml
[tool.skylos.whitelist.temporary]
"legacy_handler" = { reason = "Migration in progress - JIRA-123", expires = "2026-03-01" }
"old_api_v1" = { reason = "Deprecated, removing in Q2", expires = "2026-06-30" }
```

#### `[tool.skylos.overrides."path/*"]`

Per-file or per-folder whitelist rules:
```toml
[tool.skylos.overrides."src/plugins/*"]
whitelist = ["*Plugin", "*Handler"]

[tool.skylos.overrides."src/events/*"]
whitelist = ["on_*", "*_listener"]
```

## Dead-Code Entrypoints

Use `[[tool.skylos.dead_code.entrypoints]]` when code is live because a
project-specific framework, plugin loader, or decorator calls it implicitly.
Entrypoint rules are more precise than broad whitelists because they can match
definition type, name, path, decorator, base class, and parent class metadata.

```toml
[tool.skylos.dead_code]
entrypoints = []

[[tool.skylos.dead_code.entrypoints]]
type = "class"
name = "Main"
path = "**/main.py"
base_classes = ["Application"]
reason = "framework application entrypoint"

[[tool.skylos.dead_code.entrypoints]]
type = "method"
name = ["create", "pre_hook", "post_hook"]
parent = { name = "Main", base_classes = ["Application"] }
reason = "framework lifecycle method"

[[tool.skylos.dead_code.entrypoints]]
type = "function"
decorators = ["runtime_hook"]
path = "src/**"
reason = "registered by runtime_hook"
```

Supported match fields are `type`, `name`, `full_name`, `module`, `path`,
`decorator`, `decorators`, `base_class`, `base_classes`, and `parent`. The
`parent` rule can match the parent class by `name`, `full_name`, `module`,
`path`, `base_class`, or `base_classes`. Rules must include a symbol selector
such as `name`, `decorators`, `base_classes`, or `parent`; `path`, `module`,
and `type` only narrow the match.

### Inline Ignores

For one-off exceptions, use inline comments instead of config. Inline comments
work in Python, TypeScript/JavaScript (with `//`) and CI/config files. Go,
Java, PHP, Rust, Dart, C#, Kotlin, C/C++ and shell have no inline form: use
`ignore`, the whitelist, a baseline or `skylos review`.

```python
# Single line ignore
def dynamic_handler():  # skylos: ignore
    pass

# Alternative syntaxes (all equivalent)
def another():  # noqa: skylos
    pass

def yet_another():  # pragma: no skylos
    pass

# Block ignore (multiple functions)
# skylos: ignore-start
def block_one():
    pass

def block_two():
    pass
# skylos: ignore-end

# Only one rule on this line
query = build(sql)  # skylos: ignore[SKY-D211] reviewed, input is constant
```

Notes:

- A rule-scoped marker such as `# skylos: ignore[SKY-D211]` hides only that
  rule. It does not hide dead-code findings. Use the blanket
  `# skylos: ignore` for those.
- A bare `# noqa` does not hide HIGH or CRITICAL security (`SKY-D`) or secret
  (`SKY-S`) findings.
- `# noqa: F401` and `# noqa: F841` hide unused imports and unused variables.
- `skylos: ignore-start` without `skylos: ignore-end` runs to the end of the
  file.

### Whitelist Summary

| Want to... | Do this |
|------------|---------|
| Whitelist a pattern | `skylos whitelist 'handle_*'` or add to `names = []` |
| Document why | `skylos whitelist x --reason "why"` or add to `[tool.skylos.whitelist.documented]` |
| Temporary whitelist | Add to `[tool.skylos.whitelist.temporary]` with `expires` date |
| Per-folder rules | Add `[tool.skylos.overrides."path/*"]` section |
| View all whitelists | `skylos whitelist --show` |
| Inline ignore | `# skylos: ignore` comment |
| Block ignore | `# skylos: ignore-start` ... `# skylos: ignore-end` |

## Language-Specific Overrides

You can override global settings for specific languages under `[tool.skylos.languages.<lang>]`:
```toml
[tool.skylos.languages.typescript]
complexity = 15
nesting = 4

[tool.skylos.languages.java]
complexity = 12
```

Only `complexity` can be overridden, and only for `typescript` and `java`.

## Configuration Resolution

Skylos looks for config in the scanned folder, then in each parent folder up to
the folder that holds `.git`.

- In one folder, the first of `.skylos.toml`, `skylos.toml` and
  `pyproject.toml` (with `[tool.skylos]`) is used.
- Files closer to the scanned path win, key by key. The tables `gate`,
  `vibe`, `architecture`, `contribution`, `dead_code` and `masking` merge
  per key. Other keys, lists included, are replaced.
- `root = true` in a file stops the walk at that folder.
- With no config, Skylos uses its built-in defaults.

To use one file and skip discovery:

```bash
skylos . --config-file path/to/skylos.toml
```

`SKYLOS_CONFIG_FILE=path/to/skylos.toml` does the same.

Some settings are read only from the repository root `pyproject.toml`:
`nudges`, `hooks_allow_packages` and `[tool.skylos.hooks]`. The done gate
(`[tool.skylos.done]`) and risk review (`[tool.skylos.approval]`) read the root
config from the base commit, so a change cannot loosen its own check.

A `.skylos/config.yaml` file holds policy synced from Skylos Cloud by
`skylos sync pull`. It overrides the repository's gate limits, excludes and
ignores. `skylos sync pull` also writes `.skylos/suppressions.json`, but local
scans do not read that file today.

## Default Excluded Folders

Skylos automatically excludes common non-source directories:
```
*.egg-info  .coverage  .git  .hg  .idea  .mypy_cache  .next  .nuxt
.pytest_cache  .svn  .tox  .turbo  .venv  .vscode  __pycache__  build
dist  htmlcov  node_modules  vendor  venv
```

It also skips generated and vendored files by default: Django migrations,
`*.min.js`, `*.min.css`, `static/**/lib/**` and files that open with a vendored
licence banner. Use `--include-generated` or `include_generated = true` to scan
them.

To see the current exclusion list:
```bash
skylos . --list-default-excludes
```

To disable default exclusions:
```bash
skylos . --no-default-excludes
```

To force-include a normally excluded folder:
```bash
skylos . --include-folder venv
```
