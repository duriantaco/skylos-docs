## The Hidden Cost of Dead Code

Dead code isn't just clutter. It's **active technical debt** that:

- **Slows Development** - Developers read and reason about code that does nothing
- **Hides Bugs** - Unused code paths can mask logic errors and security issues
- **Increases Attack Surface** - Vulnerable code that's "not used" can still be exploited
- **Bloats Bundles** - Unused imports increase load times and memory usage

**The problem?** Removing code is scary. What if it's actually used somewhere you didn't check?

## How Skylos Finds Dead Code

Skylos builds a complete **reference graph** of your codebase, then identifies definitions with zero references.
```mermaid
flowchart TB
    subgraph Phase1["Phase 1: Collection"]
        A[Parse all files] --> B[Collect definitions]
        B --> C[Collect references]
    end
    
    subgraph Phase2["Phase 2: Resolution"]
        D[Build reference graph]
        E[Resolve imports to originals]
        F[Handle dynamic access]
    end
    
    subgraph Phase3["Phase 3: Scoring"]
        G[Cross-reference defs vs refs]
        H[Apply framework rules]
        I[Calculate confidence]
    end
    
    Phase1 --> Phase2
    Phase2 --> Phase3
    
    I --> J{Confidence > Threshold?}
    J -->|Yes| K["Report as unused"]
    J -->|No| L["Likely used"]
    
    style K fill:#ff6b6b,color:#fff
    style L fill:#2ed573,color:#fff
```

### What Gets Detected

| Category | Rule | Example | Detection Method |
|----------|------|---------|------------------|
| **Unused functions** | `SKY-U001` | `def helper(): ...` never called | No call references found |
| **Unused imports** | `SKY-U002` | `import json` but `json` never used | No name references found |
| **Unused variables** | `SKY-U003` | `result = compute()` but `result` never read | Assigned but never referenced |
| **Unused classes** | `SKY-U004` | `class OldModel: ...` never instantiated | No instantiation or inheritance |
| **Unused parameters** | `SKY-U006` | `def fn(a, b): return a` | Parameter `b` never used in body |
| **Unused files** | `SKY-E003` | A TypeScript/JavaScript file nothing imports | No import of the file found |

Unreachable code (`SKY-UC001`, `SKY-UC002`) and unused dependencies
(`SKY-U005`) are dead-code findings too, but they only run with `--quality`.

Unused parameters are capped at confidence 50, so they are hidden at the
default threshold of 60. Use `--confidence 40` to see them.

### Languages

Coverage is not the same in every language:

| Language | What dead-code detection covers |
|----------|---------------------------------|
| Python | Deepest support: functions, classes, imports, variables, parameters, framework rules |
| TypeScript / JavaScript | Functions, classes, imports, unused files (`SKY-E003`), unnecessary exports (`SKY-E004`) |
| Java, Go, PHP | Unused symbols; Go needs the bundled `skylos-go` engine |
| Kotlin | Private symbols and imports only |
| Rust | Experimental. Findings are capped at confidence 40, so they are hidden at the default threshold of 60. Use `--confidence 40` to see them |
| Dart | Needs `pip install "skylos[dart]"` |
| C# | Partial |
| C++ | File-local functions only |

See [Language Support](/language-support) for details.

## The Confidence System

Not all "unused" code is actually dead. A helper function might be:

- Called dynamically via `getattr()`
- Used by a framework implicitly
- Part of a public API

Skylos assigns a **confidence score** (0-100) to each finding, so you can filter out uncertain results.
```mermaid
flowchart LR
    A["Initial: 100%"] --> G{"Framework decorator?"}
    G -->|Yes| H["Not reported"]
    G -->|No| B{"Private name? _helper"}
    B -->|Yes| C["-10%"]
    B -->|No| D[Keep]

    C --> E{"Dunder method? __str__"}
    D --> E

    E -->|Yes| F["-100% (Excluded)"]
    E -->|No| I{"Function or class in __init__.py?"}

    I -->|Yes| J["-15%"]
    I -->|No| K[Final Score]
    J --> K

    style F fill:#2ed573,color:#fff
    style H fill:#2ed573,color:#fff
    style K fill:#ffa502,color:#fff
```

### Confidence Penalties

| Pattern | Penalty | Reason |
|---------|---------|--------|
| Private name (`_foo`, Python) | -10 | Convention for internal use |
| Dunder (`__str__`) | -100 | Called implicitly by Python |
| Underscore var (`_`) | Not reported | Intentionally unused |
| Function or class in `__init__.py` | -15 | Often public API re-exports |
| Framework decorator (route, signal, fixture) | Not reported | Called by the framework |
| Dynamic module | -10 | May use `getattr()` |
| Test decorator | -100 | Called by test runner |

### Confidence Caps

Some findings can never reach 100%, because the code may still be used from
outside the scan:

| Finding | Highest confidence |
|---------|--------------------|
| Public Python function, class or variable | 90 |
| Exported but never imported | 85 |
| Public method (dynamic dispatch possible) | 80 |
| Class attribute (frameworks may read it) | 80 |
| File no import loads | 80 |
| Only reachable through a dynamic lookup | 70 |
| Default export | 60 |
| Parameter | 50 |
| Rust (experimental) | 40 |
| Deprecated API kept for callers | 40 |

The report shows the reason next to the score, for example
`Confidence: 90% (public name)`.

### Using Confidence Threshold
```bash
# Default: only findings with ≥60% confidence
skylos .

# Include more uncertain findings
skylos . --confidence 40

# Only high-confidence findings
skylos . --confidence 80
```

## Framework Awareness

Skylos understands that framework code is called implicitly:

<Tabs>
  <TabItem value="django" label="Django" default>
```python
# Not flagged - Django calls this via URL routing
def user_detail(request, pk):
    return render(request, 'user.html', {'user': User.objects.get(pk=pk)})

# Not flagged - Signal receiver
@receiver(post_save, sender=User)
def create_profile(sender, instance, **kwargs):
    Profile.objects.create(user=instance)

# Not flagged - Class-based view methods
class UserView(View):
    def get(self, request):
        return HttpResponse("Hello")
```

  </TabItem>
  <TabItem value="flask" label="Flask / FastAPI">
```python
# Not flagged - Route handler
@app.route('/users')
def get_users():
    return jsonify(users)

# Not flagged - Error handler
@app.errorhandler(404)
def not_found(e):
    return "Not found", 404

# Not flagged - FastAPI dependency
async def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

  </TabItem>
  <TabItem value="pydantic" label="Pydantic">
```python
# Not flagged - Pydantic model
class UserCreate(BaseModel):
    name: str
    email: str

# Not flagged - Validator
@field_validator('email')
def validate_email(cls, v):
    if '@' not in v:
        raise ValueError('Invalid')
    return v
```

  </TabItem>

def db_session():

    user = User(name='Test')

## Custom Entrypoints

For proprietary frameworks, plugin loaders, and decorator registries, add
project-specific entrypoint rules instead of broad whitelists:

```toml
[[tool.skylos.dead_code.entrypoints]]
type = "method"
name = ["create", "pre_hook", "post_hook"]
parent = { name = "Main", base_classes = ["Application"] }
reason = "project framework lifecycle hook"

[[tool.skylos.dead_code.entrypoints]]
type = "function"
decorators = ["runtime_hook"]
path = "src/**"
reason = "registered by runtime_hook"
```

Skylos treats matching definitions as live while still reporting unrelated
dead code in the same files. See [Configuration](/configuration) for every
supported match field. Entrypoint rules must include a symbol selector such as
`name`, `decorators`, `base_classes`, or `parent`; `path`, `module`, and
`type` only narrow the match.

## Smart Tracing (Runtime Analysis)

Static analysis can't catch everything. When code is called dynamically via `getattr()`, visitor patterns, or reflection, Skylos may flag it as unused.

**The solution:** Run your tests with call tracing enabled.
```bash
skylos . --trace
```

This:
1. Runs your test suite with `sys.settrace()` enabled
2. Records every function that was actually called
3. Uses that data to eliminate false positives

### What Gets Captured

| Pattern | Static Analysis | With `--trace` |
|---------|----------------|----------------|
| `visitor.visit(node)` → `visit_FunctionDef()` | Missed | Caught |
| `getattr(obj, "method")()` | Missed | Caught |
| Plugin hooks (`pytest_configure`) | Missed | Caught |
| Reflection / dynamic imports | Missed | Caught |

### When to Use `--trace`

**Use It:**
- Projects with visitor patterns (AST, CST)
- Plugin architectures
- Heavy use of `getattr()` / reflection
- Many false positives from static analysis

**Skip It:**
- Simple codebases with direct calls
- No test suite available
- CI where speed matters (tracing adds overhead)

### How It Works
```mermaid
flowchart LR
    A[skylos . --trace] --> B[Run pytest with sys.settrace]
    B --> C[Record all function calls]
    C --> D[Save to .skylos_trace]
    D --> E[Static analysis]
    E --> F[Cross-reference with trace]
    F --> G[Remove false positives]
```

:::tip
**Tip:** Commit `.skylos_trace` to your repo if your test suite is stable. Then `skylos .` will use it automatically without re-running tests.
:::

## Safe Removal Workflow

### 1. Scan with high confidence

Start with findings you can trust:
```bash
skylos . --confidence 80
```

### 2. Preview deterministic cleanup

For Python unused import/function cleanup, preview the exact edits first:

```bash
skylos clean . --dry-run --types import,function --confidence 80
```

### 3. Apply selected cleanup

Apply the same deterministic cleanup without prompts:

```bash
skylos clean . --apply --types imports --confidence 80
```

Use comment-out mode when you want a reversible source marker:

```bash
skylos clean . --apply --comment-out --types import,function --confidence 80
```

`skylos clean` edits Python unused imports and unused functions only. It
skips other finding types and other languages, and uses Python LibCST
codemods rather than regex edits. With no mode flag, it interactively selects
edits and can write after final confirmation. `--dry-run` never writes. A
completed apply pass can still exit `0` after printing an individual transform
failure, so review its completion output.

### 4. Review in interactive mode

Select what to remove. Interactive mode needs an interactive terminal, so it
does not run in CI:
```bash
skylos . -i --dry-run
```

### 5. Remove or comment out interactively
```bash
# Delete selected items
skylos . -i

# Or comment out (safer)
skylos . -i --comment-out
```

### 6. Run tests

Verify nothing broke:
```bash
pytest
```

### Comment-Out Mode

Instead of deleting, Skylos can comment out code with a marker:
```python
# Before
def unused_helper():
    return "I'm not used"

# After --comment-out
# SKYLOS DEADCODE: def unused_helper():
# SKYLOS DEADCODE:     return "I'm not used"
```

Search for `SKYLOS DEADCODE` later to permanently remove or restore.
