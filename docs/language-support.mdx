Skylos scans mixed-language repositories in one pass. Source files are discovered
by extension, parsed with the language-specific frontend, and normalized into
the same finding model used by the CLI, CI gate, JSON output, SARIF output, MCP
server, and Cloud upload.

## Support Matrix

| Language | Extensions | Dead Code | Security | Quality | Notes |
|:---|:---|:---:|:---:|:---:|:---|
| Python | `.py` | Yes | Yes | Yes | Strongest coverage, framework-aware analysis, optional runtime tracing, and AI repair |
| TypeScript / JavaScript | `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs` | Yes | Yes | Subset | Tree-sitter parsing, package graph reachability, React and Next.js awareness |
| Java | `.java` | Yes | Yes | Selected | Tree-sitter parsing, Java data-flow security checks, and method quality metrics |
| Go | `.go` | Yes | Selected | Selected | Needs the bundled `skylos-go` engine for dead code and security |
| Kotlin | `.kt`, `.kts` | Private symbols | Secrets only | No | Reports only `private` symbols and unused imports; no Kotlin security rules |
| PHP | `.php` | Yes | Selected | No | PHP parser coverage with selected SQL, file, include, and deserialization checks |
| Rust | `.rs` | Experimental | Selected | No | Hidden at the default confidence; use `--confidence 40` to see Rust candidates |
| Dart | `.dart` | Yes | Selected | No | Needs `pip install "skylos[dart]"`; Flutter and test entry points handled |
| C# | `.cs` | Partial | Selected | Unreachable code only | C# symbol coverage plus selected ASP.NET, process, SQL, HTTP, redirect, and file sinks |
| C++ | `.cpp`, `.cc`, `.cxx` | File-local functions | No | No | Reports only unused file-local functions; headers are read for references |
| Shell | `.sh`, `.bash`, `.zsh`, `.ksh`, `.bats` | No | Selected | No | Static shell checks for command injection, SSRF, and path traversal |

## Config And Deployment Support

Skylos also scans security-relevant configuration and deployment files when
security analysis is enabled. These checks are reported with the same finding
model as source-code rules.

| Surface | Files | Security Scope |
|:---|:---|:---|
| GitHub Actions | `.github/workflows/*.yml`, `.github/workflows/*.yaml`, `action.yml`, `action.yaml` | dangerous triggers, token permissions, unpinned actions, template injection, secrets, OIDC, cache, and artifact policy |
| GitLab CI | `.gitlab-ci.yml` | mutable images, unpinned includes, literal secrets, untrusted eval, Docker-in-Docker, OIDC, cache, timeout, and runner-tag policy |
| Dockerfile | `Dockerfile`, `Dockerfile.*`, `*.dockerfile` | dangerous `RUN` commands, remote `ADD` without checksum, and literal build `ARG` / `ENV` secrets |
| Edge Docker Compose | `compose*.yml`, `compose*.yaml`, `docker-compose*.yml`, `docker-compose*.yaml` | privileged containers, host device/control mounts, GPU/device runtime, and host networking |
| Edge systemd | `*.service` | root edge services, mutable `ExecStart` paths, missing sandboxing, broad capabilities, and broad device access |

`Selected` means the scanner covers a few high-signal rules for that language.
Coverage is narrower than Python, TypeScript/JavaScript, and Java.

`Secrets only` means `--secrets` scans the files for hard-coded credentials.
There are no language-specific security rules.

`Subset` and `Selected` quality: TypeScript/JavaScript has complexity, nesting,
length, argument-count and a few logic rules. Java and Go have complexity
(`SKY-Q301`), nesting (`SKY-Q302`), argument count (`SKY-C303`) and function
length (`SKY-C304`). C# has only unreachable code (`SKY-UC002`).

## Known Limits

- **Rust dead code is experimental.** Candidates are capped at confidence 40.
  The default threshold is 60, so they are not listed. The scan prints one line
  that says so. Run `skylos . --confidence 40` to see them.
- **Kotlin dead code covers only `private` symbols and imports.** Anything
  visible outside its file is treated as used.
- **Java secrets need `--danger`.** `--secrets` alone skips `.java` files. Use
  `skylos . --danger --secrets` or `-a`.
- **Secrets are not scanned** in shell scripts, Dockerfiles, or C++ files.
  Literal secrets in GitHub Actions, GitLab CI and Dockerfile `ARG`/`ENV` are
  covered by the config rules below when `--danger` is on.
- **Go needs the `skylos-go` engine.** PyPI wheels, the container image and the
  GitHub Action include it. Without it, only Go quality checks run and the Go
  files are reported as not analysed. `skylos doctor` shows whether it is
  installed.
- **Dart needs the extra.** Install `pip install "skylos[dart]"` (needs a C
  compiler). Without it, `.dart` files are reported as not analysed.
- **`skylos verify` API proof** covers Python, TypeScript/JavaScript, Go and
  Java. Other languages report it as unsupported, so the result is
  `incomplete`.
- **Inline suppression comments** work in Python, TypeScript/JavaScript and the
  config files below. Go, Java, PHP, Rust, Dart, C#, Kotlin, C++ and shell have
  no inline form. Use `[tool.skylos] ignore`, `skylos whitelist`, a baseline or
  `skylos review` instead.

## Coverage By Language

| Language | What Skylos does today |
|:---|:---|
| Python | Deep dead-code analysis with framework awareness, runtime trace support, security rules, secrets, quality, technical debt, repository policy, and AI repair workflows |
| TypeScript / JavaScript | Dead-code and package graph analysis, React/Next.js awareness, client-side secret exposure, browser/server security sinks, quality rules, and monorepo inventory |
| Java | Parser-backed dead-code detection, dangerous-call security checks, taint-style sink checks, weak crypto detection, and method quality metrics |
| Go | Module-aware scanning through the `skylos-go` engine, Go-specific security rules, unified cross-language security IDs, and function quality checks |
| Kotlin | Unused `private` functions, methods and types, unused imports, and shared secret scanning of `.kt` / `.kts` files |
| PHP | Dead-code detection for PHP symbols with Laravel and Drupal conventions, plus selected SQL, filesystem/include and unsafe deserialization checks |
| Rust | Experimental dead-code candidates (hidden below confidence 40) plus command execution and filesystem path security checks |
| Dart | Dead-code coverage for Dart and Flutter-style projects plus selected process, HTTP, and filesystem checks (needs `skylos[dart]`) |
| C# | Conservative dead-code candidates for C# classes and methods, unreachable code after `return`/`throw`, plus selected process, SQL, HTTP, redirect, and filesystem security checks |
| C++ | Unused file-local functions only |
| Shell | Static security checks for CI/deploy/release scripts, focused on command injection, SSRF, and path traversal |

## How Scans Run

```bash
# Dead code across all supported source files
skylos .

# Security and quality rules where supported
skylos . --danger --quality

# Full local audit
skylos . -a
```

Skylos does not require separate commands for each language. A repository with a
Python API, a TypeScript frontend, a Go service, a Kotlin Android client, a
Dart mobile client, a C# service, and Shell deployment scripts can be scanned from the
repository root.

## Shared Behavior

Across supported languages, Skylos tries to preserve the same workflow:

- detect definitions and references for dead code analysis
- report security findings with unified `SKY-D` rule IDs when rules describe the same weakness
- honor global exclusions, confidence thresholds, and `[tool.skylos] ignore`; inline ignore comments only where the language has them (see [Known Limits](#known-limits))
- include language counts and findings in JSON, SARIF, Cloud, and MCP output
