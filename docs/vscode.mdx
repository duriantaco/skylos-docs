:::info
  **Prerequisites**:
  - VS Code version 1.87 or higher
  - Python 3.10+ (for Skylos CLI)
  - OpenAI or Anthropic API key, or a local model, only for AI fixes and chat
:::

The Skylos VS Code extension shows Skylos findings in your editor. It runs the
Skylos CLI on Python, TypeScript, JavaScript and Go files. Edit-time
verification and AI fixes are optional.

## Installation

### 1. Install the extension

Search for "Skylos" in the VS Code marketplace, or install directly:

**VS Code:**
```bash
ext install oha.skylos-vscode-extension
```

### 2. Install the Skylos CLI

The extension uses the Skylos CLI for static analysis. Install it with pip:

**pip:**
```bash
pip install skylos
```

Verify the installation:

**bash:**
```bash
skylos --version
```

### 3. Add your API key for fixes

Scans and the edit-time verifier use the local CLI and need no key. Add an
OpenAI or Anthropic API key only if you want the extension to generate fixes or
answer questions:

1. Open VS Code Settings (`Cmd + ,` on Mac, `Ctrl + ,` on Windows)
2. Search for `skylos`
3. Add your API key to `skylos.openaiApiKey` or `skylos.anthropicApiKey`

**settings.json:**
```json
{
  "skylos.openaiApiKey": "sk-...",
  "skylos.aiProvider": "openai"
}
```

## How It Works

The extension provides two layers of protection:

### Layer 1: Skylos CLI (on save)

When you save a Python, TypeScript, JavaScript or Go file, the Skylos CLI scans
that file and detects:
- Dead code (unused functions, imports, classes, variables)
- Hardcoded secrets and API keys
- Dangerous patterns (`eval`, `pickle`, `shell=True`)
- Code quality issues

Turn this off with `skylos.runOnSave`.

### Layer 2: Verify Watcher (on idle, opt-in)

This layer is off by default. Turn it on with `"skylos.enableRealtimeAI": true`
in a trusted workspace. It does not call an AI model.

When you stop typing, the extension sends the unsaved buffer to `skylos verify`
through stdin and scopes the result to the changed function range. The verifier
returns machine-readable AI-code trust findings, including:

- hallucinated references and missing helpers
- unfinished generated code
- stale references after refactors
- disabled security controls
- API/dependency hallucinations, assertion weakening, and diff-aware AI-defect signals, reported under `ai_defects`

## Features

### Real-time Analysis

The verify watcher only analyzes functions that have changed, using content
hashing to skip unchanged code. Results are cached for 60 seconds, and the
extension logs the exact local command in the Skylos output channel.

### CodeLens Buttons

When the AI finds an issue, clickable buttons appear above the error line:

- **Fix with AI** — Generates a fix and shows a diff preview
- **Dismiss** — Removes the diagnostic without adding a pragma comment

### Streaming Fixes

When you click "Fix with AI", the extension streams the response from the LLM. You'll see progress in the status bar:

**Status bar:**
```
$(sync~spin) Fixing... 234 chars
```

### Diff Preview

Before applying any fix, you'll see a side-by-side diff comparing your original code with the AI's suggestion. Click "Apply" to accept or "Cancel" to reject.

## Configuration

All settings are under the `skylos.*` namespace:

| Setting | Default | Description |
|---------|---------|-------------|
| `skylos.path` | `"skylos"` | Path to the Skylos CLI executable |
| `skylos.aiProvider` | `"openai"` | AI provider for chat and fixes |
| `skylos.openaiApiKey` | `""` | Your OpenAI API key |
| `skylos.anthropicApiKey` | `""` | Your Anthropic API key |
| `skylos.openaiModel` | `"gpt-4o"` | OpenAI model |
| `skylos.anthropicModel` | `"claude-sonnet-4-20250514"` | Anthropic model |
| `skylos.localBaseUrl`, `skylos.localModel` | `""` | A local AI server, such as Ollama at `http://localhost:11434` |
| `skylos.enableRealtimeAI` | `false` | Run `skylos verify` after you pause editing |
| `skylos.idleMs` | `1000` | Milliseconds to wait after typing stops |
| `skylos.popupCooldownMs` | `8000` | Cooldown between popup alerts |
| `skylos.runOnSave` | `true` | Scan the saved file |
| `skylos.enableSecrets` | `true` | Scan for hardcoded secrets |
| `skylos.enableDanger` | `true` | Flag dangerous code patterns |
| `skylos.enableQuality` | `true` | Include code quality checks |
| `skylos.enableDeadCode` | `true` | Show dead-code findings |
| `skylos.confidence` | `80` | Dead-code confidence threshold (0-100) |
| `skylos.diffBase` | `"origin/main"` | Base ref for "new issues only" mode |
| `skylos.excludeFolders` | `["venv", ".venv", "build", "dist", ".git", "__pycache__", "node_modules", ".next"]` | Folders to exclude |

:::note
The extension's default confidence is `80`. The CLI's default is `60`. So the
editor shows fewer dead-code findings than `skylos .`. Set
`"skylos.confidence": 60` to match the CLI.
:::

### Using Claude instead of GPT

To use Anthropic's Claude:

**settings.json:**
```json
{
  "skylos.aiProvider": "anthropic",
  "skylos.anthropicApiKey": "sk-ant-...",
  "skylos.anthropicModel": "claude-sonnet-4-20250514"
}
```

### Adjusting sensitivity

If the AI is too noisy, increase the idle time:

**settings.json:**
```json
{
  "skylos.idleMs": 5000,
  "skylos.popupCooldownMs": 30000
}
```

## Commands

| Command | Description |
|---------|-------------|
| `Skylos: Scan Workspace` | Scan the whole workspace (`Cmd/Ctrl + Alt + S`) |
| `Skylos: Scan This File` | Scan the current file |
| `Skylos: Fix Issue with AI Assist` | Fix the issue at the cursor with AI |
| `Skylos: Auto-Fix All with AI Assist` | Fix many findings with AI (`Cmd/Ctrl + Alt + F`); a dry-run variant previews first |
| `Skylos: Preview Dead Code Removal` | Preview removal of dead code (runs `skylos agent verify --fix`, which needs an LLM) |
| `Skylos: Ask AI About Finding` | Chat about one finding |
| `Skylos: Toggle New Issues Only` | Show only findings new since `skylos.diffBase` |
| `Skylos: Next Finding` / `Previous Finding` | Jump between findings (`Cmd/Ctrl + Alt + ]` and `[`) |
| `Skylos: Add to Whitelist` | Mark a dead-code name as intentionally used |
| `Skylos: Security Dashboard` | Open the findings dashboard |
| `Skylos: Export Report` | Export the current findings |
| `Skylos: Doctor` | Check that the extension can run the CLI |

Access commands via the Command Palette (`Cmd + Shift + P`).

## Quick Fix Menu

When you see a squiggly line, click the lightbulb or press `Cmd + .` to see quick fix options:

- **Skylos: ignore on this line** — adds a Skylos ignore comment to that line

The CLI honours the same inline comments. See
[Configuration](./configuration#inline-ignores) for the syntax per language.

## Output Panel

Findings appear in the Problems panel (`Cmd + Shift + M`) and in the Skylos
sidebar. Dead-code findings stay out of the Problems panel unless
`skylos.showDeadCodeInProblems` is on.

The Output panel shows what the extension runs:

1. Open Output (`Ctrl + Shift + U`)
2. Select "skylos" from the dropdown

It logs each CLI command, its errors, and the `Skylos: Doctor` report.

## Troubleshooting

<details>
<summary>Issue: "Skylos failed: command not found"</summary>

The Skylos CLI is not installed or not in your PATH.

**Solution:**
1. Install the CLI: `pip install skylos`
2. Or set the full path in settings: `"skylos.path": "/path/to/skylos"`
</details>

<details>
<summary>Issue: AI features not working</summary>

Check that you've added your API key:

1. Open Settings (`Cmd + ,`)
2. Search for `skylos.openaiApiKey` or `skylos.anthropicApiKey`
3. Paste your API key

Also verify `skylos.aiProvider` matches your key type.
</details>

<details>
<summary>Issue: No popups appearing</summary>

Popups only appear for critical and high findings (turn them off with
`skylos.showPopup`). They also have a cooldown (default 8 seconds) and won't
show the same issue twice.

To see all issues, check the Problems panel (`Cmd + Shift + M`) or the Output panel.
</details>

<details>
<summary>Issue: Python version errors with Skylos CLI</summary>

Skylos requires Python 3.10+. Check your version:
```bash
python --version
```

If you're on an older version, upgrade Python or use a virtual environment with 3.10+.
</details>

<details>
<summary>Issue: "TypeError: unsupported operand type(s) for |"</summary>

This happens when running Skylos with Python 3.9 or earlier. The `|` type union syntax requires Python 3.10+.

**Solution:** Upgrade to Python 3.10 or higher.
</details>

## Privacy

- **Skylos CLI** runs locally. Dependency checks send package names and versions to public registries
- **Realtime verify** uses `skylos verify` locally and does not send code to an LLM provider
- **Fix with AI** sends only the code needed for the selected fix to OpenAI/Anthropic
- Your API keys are stored in VS Code settings (local to your machine)
- No telemetry or analytics are collected
