# Case Studies

## Cleanup PRs in open-source projects

This ledger covers 26 Skylos-assisted cleanup and quality pull requests in 22 open-source
projects between March and July 2026. Candidates came from Skylos static analysis, and many were also triaged with
`skylos agent verify`, which uses an LLM. Maintainers merged 10 dead-code cleanup PRs into the
default branch of 9 open-source projects, excluding the known
[Glances revert](https://github.com/nicolargo/glances/commit/f72edef56a9759b5824fead73bd0462d5298df51).
One more, in Flagsmith, was
merged into a maintainer's staging branch, but the change did not reach main. These are maintainer
decisions on cleanup PRs, not endorsements or adoption of Skylos.

Merge and closure states and branch destinations were checked on GitHub on 9 October 2026.
These counts record pull-request outcomes, excluding the known Glances revert. We have not
performed a fresh audit of whether every removed symbol remains absent from the current default branches.

The other 16 pull requests and their outcomes are listed in
[REAL_WORLD_RESULTS.md](https://github.com/duriantaco/skylos/blob/main/REAL_WORLD_RESULTS.md),
including the reverted one, the four a maintainer closed, and the Flagsmith PR
([Flagsmith/flagsmith#6953](https://github.com/Flagsmith/flagsmith/pull/6953)): a maintainer merged
it into a staging branch so CI could run, and the follow-up PR to main
([#6955](https://github.com/Flagsmith/flagsmith/pull/6955)) was closed unmerged.

What they taught us:

- Public API is not dead code, even when nothing in the repository calls it.
- A stale branch can make dead code live again. Re-check on current main the day you submit.
- Run the project's own formatter and linters before opening the pull request.

## Done-gate benchmark

`skylos done` was measured on published coding-agent runs with published labels: runs that
cheated to pass tests, and honest runs. The write-up gives the pinned dataset, the harness, the
results for each check, and the limits, including what the gate does not catch: it did not catch
edits to test data files. The check for code that special-cases tests was developed against this
data, so its results are in-sample.

Read it at
[docs/done-gate-benchmark.md](https://github.com/duriantaco/skylos/blob/v4.47.2/docs/done-gate-benchmark.md)
(Skylos 4.47.2). See [Done Gate](/done-gate) for what the gate checks.
